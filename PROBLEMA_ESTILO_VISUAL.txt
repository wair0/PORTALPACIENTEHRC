PROBLEMA ACTUAL - ESTILO VISUAL
================================

Fecha: 2026-10-10

DESCRIPCIÓN
----------
El portal oficial (My Companion / Philips) carga y funciona correctamente dentro del WebView.
El usuario puede loguearse y navegar por todas las secciones.

Sin embargo, el estilo visual personalizado de la app NO se aplica correctamente.
El resultado es una mezcla de ambos estilos, que se ve mal:

- El header oficial del portal sigue apareciendo debajo del header nativo de la app.
- El header nativo de la app se ve básico (no se aplica el diseño completo).
- La barra inferior nativa se ve básica.
- Los componentes del portal mantienen gran parte de su estilo original.

LO QUE SE INTENTÓ
-----------------
1. Inyección de CSS + JS (portal-theme.css + enhancer.js) vía PortalInjector.
2. Versiones más agresivas de CSS para ocultar headers/footers oficiales.
3. Enhancer que intenta ocultar el header oficial por selectores y por posición.
4. Tema v6 del zip DISEÑO.zip (clasificación por data-hrc).
5. Inyección segura esperando document.head.

RESULTADO
---------
El estilo del portal oficial sigue predominando. Los intentos de ocultar el header oficial no son suficientes o se aplican demasiado tarde.

POSIBLES CAUSAS
---------------
- El CSS del portal se carga después o tiene mayor especificidad.
- Los selectores del enhancer no coinciden con la estructura real del DOM del portal.
- La inyección ocurre demasiado temprano o demasiado tarde.
- El portal usa Shadow DOM o estilos inline que no se pueden sobrescribir fácilmente.

PRÓXIMOS PASOS SUGERIDOS
------------------------
1. Inspeccionar el DOM real del portal (con el panel de debug o chrome://inspect) para identificar los selectores exactos del header oficial.
2. Aplicar el CSS con mayor especificidad o !important en más reglas.
3. Evaluar si es viable ocultar el header oficial de forma confiable o si conviene diseñar el estilo asumiendo que el header oficial estará presente.
4. Revisar el zip DISEÑO.zip para confirmar que los archivos se aplicaron correctamente.

Este archivo sirve como registro del estado actual del problema.
